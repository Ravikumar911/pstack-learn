If you want to go fast, go deep first.

pstack is a Cursor plugin by poteto. It makes agents work like a careful engineering team. You write less code, and it's better code. Three commands get you going.

1 · INSTALL
/add-plugin pstack

Run it in a Cursor chat.

2 · PICK MODELS
/setup-pstack

Choose a reasoning budget and a model per role. It writes ~/.cursor/rules/pstack-models.mdc. Start a new chat after.

3 · GIVE IT A GOAL
/poteto-mode the export writes duplicate rows when a retry lands mid-run. repro first, then fix and verify.

Say the goal and a check that can pass or fail. It picks the playbook.

Stuck? Type /poteto-help with your question. It answers and hands you a prompt to send, but doesn't start the work. To keep /poteto-mode on every turn, pick it from the / menu with Option+Enter (Mac) or Alt+Enter (Windows).

When setup offers /create-verification-skill, say yes. An agent that can check its own work keeps going until the check passes. The guide calls it the part that pays off most.

Write the prompt

You don't name playbooks or list skills. You say what you want and how you'll know it's done.

  • The goal. What's wrong, or what you want.
  • The done check. It must be able to pass or fail. "Make it better" isn't one.
  • The proof you want. Real command output, a video, the stored value, a before-and-after number.
  • What you already know. A symptom, a repro step, a log line.
  • Real constraints. "repro first", "don't change any code yet", "zero behavior change".
/poteto-mode the csv export drops its last row since yesterday's deploy. failing job id is 4812. repro first, then fix. done means the 60k-row fixture exports every row. show me the row counts before and after.

Leave out the how, and hold your theory of the cause until the agent has restated the problem. Change subjects with "new task". Steer a drifting run with a principle name.

apply prove it works. show me the real output, not the build log.

pstack spends extra tokens on subagents and review panels. To spend less, pick a smaller budget in /setup-pstack, set a role to auto, shorten a panel list, or skip /poteto-mode for small obvious edits.

Pitfalls

  • Listing skills in the prompt. The playbook already sequences them. Name a skill only to override a choice.
  • A vague finish condition. /loop needs a command or artifact that can pass or fail.
  • Parallel agents in one worktree. Use cloud agents, or ask for its own worktree per attempt.
  • Looping before you trust the loop. Get the verification skill working first.
  • Success off a green build. A build proves it compiles. Ask for the real flow, value, or profile.
  • Treating auto as a model slug. It means the role runs on the parent chat model.
